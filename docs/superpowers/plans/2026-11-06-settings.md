# Application Settings Implementation Plan

> **For agentic workers:** Execute inline using superpowers:executing-plans,
> with test-driven-development and review before completion.

**Goal:** Persist and observe the user's preferred promotion destination.

**Architecture:** A common `AppSettings` interface hides a Preferences DataStore
adapter. JVM code supplies native path validation and one process-wide store;
tests inject isolated storage and lifecycle scopes.

**Tech Stack:** Kotlin Multiplatform, AndroidX DataStore 1.3.0, coroutines,
existing Kotest assertions and JUnit Jupiter.

**Spec:** `docs/superpowers/specs/2026-11-06-settings-design.md`

## Global constraints

- Common Kotlin API; JVM/Windows production backend only.
- Native absolute paths retained verbatim; unavailable folders accepted.
- No silent defaults on errors, corruption repair, or real user settings in tests.
- One active process, one shared production store; no UI or promotion wiring.
- Reuse TestVolumes fixtures for the optional NTFS/ReFS integration matrix.
